For non-technical, business/lawyer/client-facing reference docs, write **plain prose with simple bullet lists** — NOT markdown tables, and NO technical clutter (URL routes like `/panel/scanner`, code symbol names like `canScanTickets`, file paths). Keep it simple and easy to read.

**Why:** Santiago (CEO, non-coder) asked for "a simple easy-to-read doc"; reacted strongly ("dont give me tables like wtf", "Idk why you're giving me 'ruta' and shit") to a tables+routes layout on a MUNET lawyer-reference doc (2026-06-27).

**How to apply:** Bold the item name, follow with ≤2 plain-Spanish sentences. Use bullets for lists of modules/services. Reserve tables and route/symbol detail for internal engineering docs only. Default business deliverables to clean prose. Relates to [[feedback_quiet_when_impatient]] and [[feedback_no_option_menus]].
